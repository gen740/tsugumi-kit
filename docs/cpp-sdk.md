# Writing a C++ Card

This guide targets **the Card ABI (unreleased)**. The released worker cannot run these Cards yet.

## Return a value from `run`

A Card has the shape `(input) -> output`. Include the generated `card.hh` and define one free function. Here is the complete source for a Card with a required input port `celsius` and a required output port `fahrenheit`, both tables with a `value:double` field.

```cpp
#include "card.hh"

auto run(const Card::Inputs& input) -> Card::Output {
  using Fallback = decltype(Card::Output::fahrenheit)::value_type;
  using Celsius = Card::InputType<"celsius", Fallback>;
  const auto celsius = input.get<Celsius>("celsius");
  const double fahrenheit = celsius.value * 1.8 + 32.0;
  card::display::send(card::display::Scalar{fahrenheit, "°F"});
  Card::Output output;
  output.fahrenheit.emplace().value = fahrenheit;
  return output;
}
```

For an input of 20, the next Card receives 68 on the output port. The value also appears live, as markdown. Returning the output and displaying a value are independent operations. The [temperature conversion template](../templates/temperature-conversion/) includes the input Card, both output schemas and the wire between them.

| Card definition file | What to put there |
| --- | --- |
| `_card.json` | The Card type and input port names. Connected producers supply the input types. |
| `_inputs.fbs` | Generated by Tsugumi from the wiring. The `inputs.Inputs` root describes the connected inputs. |
| `_outputs.fbs` | A FlatBuffers catalog with a root table. Each field names an output port and its FlatBuffer table or Path type. Mark required ports with `(required)`. |
| `params.nix` | Optional flat set of current parameter values. |
| `src/*.cc` | The Card implementation, including `run`. |
| `default.nix` | Import the C++ SDK and expose `run`, `api`, and `views`. The run derivation contains `lib/main.so`. |

The `api` derivation publishes `card.hh`, its generated FlatBuffers headers,
and a README under `share/tsugumi/api/`. Use **Build SDK** in the Card editor
to see the API for the current wiring. [Card SDK contract](sdk-contract.md)

- Connected input members hold `std::optional<T>`. Use
  `input.get<T>("port")` when you need the input or
  `input.get<std::optional<T>>("port")` when it can be absent.
  A needed value that is absent produces `input_missing` with the port name.
  `Card::input_types` aliases the types available for the current wiring.
  Use `Card::InputType<"port", Fallback>` when the file must also compile
  with the port disconnected. It selects the generated type when the wire
  exists and the supplied type when the wire is absent. A Path lookup can
  use `std::filesystem::path` directly.
- A FlatBuffer table has its native object type, such as `TemperatureT`.
  A mixed-type Merge is a `std::variant` of the member object types.
  Use `std::get_if` or `std::visit` to handle the active member.
- `input.params` is the generated `Card::Params` object. A parameter named
  `threshold` is available as `input.params.threshold`.
- Each output is a `std::optional` of its port type. Assign a path to a Path
  output or use `emplace()` to construct a FlatBuffer object. Leave an optional
  output disengaged to omit it. Missing required outputs or children, null
  vector table elements, and union tags without values produce `output_invalid`.
- The C++ generator renames reserved identifiers in its headers. Use the original
  port name in `input.get`.

Pass the wiring, authored output catalog, and evaluated parameters to the SDK.

```nix
{ params, inputs }:
let
  pkgs = import <nixpkgs> { };
  sdk = import <tsugumi-kit/sdk/cpp> { inherit pkgs; };
  common = {
    inherit params;
    inputs = ./_inputs.fbs;
    outputs = ./_outputs.fbs;
  };
in
{
  run = sdk.cppCard (common // { src = ./src; });
  api = sdk.cppApi common;
  views = sdk.views;
}
```

The builder also accepts optional `buildInputs`, `cxxflags`, and `tools` lists.
Use `tools = [ pkgs.coreutils ];` to put `sort` and the other coreutils
executables on the Card's runtime `PATH`. The SDK initializes `PATH` when
the Card library loads. Use `execvp` or `posix_spawnp` with an argument array
to start a declared tool directly. See [Runtime tools](../README.md#runtime-tools).
SDK selection belongs in `default.nix`. Omit `language` from `_card.json`.

## Display a value

Use `card::display::send(value)` to publish a live update. The value's C++
type selects a bundled view.

| Value accepted by `card::display::send` | View name | Display |
| --- | --- | --- |
| `std::string_view` (including string literals) | `text` | Plain text |
| `card::display::Markdown` | `markdown` | Markdown |
| `double`, `card::display::Scalar` | `markdown` | A number with 6 significant digits and an optional bold label |
| `card::display::Table` | `table` | Column names and rows of strings |
| `card::display::Image` | `image` | Media type, image bytes and optional alt text |
| `card::display::LineChart` | `line-chart` | Named series of x/y samples |
| `card::display::Points` | `points` | Rotatable x/y/z point cloud with optional per-point colors |

```cpp
const double x[] = {0, 1, 2};
const double y[] = {0, 1, 4};
const card::display::Series series[] = {{"squared", "Squared", x, y}};
card::display::send(card::display::LineChart{series});

const float px[] = {1, 0, 0};
const float py[] = {0, 1, 0};
const float pz[] = {0, 0, 1};
const uint32_t rgb[] = {0xff4040, 0x40aa40, 0x4080ff};
card::display::send(card::display::Points{px, py, pz, rgb});
```

Each series uses equal-length finite `double` arrays. `Points` takes
equal-length `float` arrays and an optional span of packed `0xRRGGBB`
colors, one per point. The point view skips non-finite positions.
The SDK and its corresponding HTML view own the encoding.

Declare the bundled views and any custom views at the top level of the Card's
`default.nix`, alongside `run` and `exports`.

```nix
{
  run = sdk.cppCard (common // { src = ./src; });
  api = sdk.cppApi common;
  views = sdk.views ++ [
    { name = "notes"; type = "html"; blob = ./notes.html; }
  ];
}
```

Each `blob` points to a single file. Use `type = "html"` for self-contained
HTML with any JavaScript and Wasm embedded, or `type = "dawn"` for a Wasm
binary targeting the Dawn host. The SDK currently bundles HTML views.

Use `card::display::send(view, bytes)` for a custom view. The view defines the
meaning of the bytes. The host passes them on with the view name.

```cpp
const int status = card::display::send(
    "notes", card::display::text_bytes("Reading input"));
```

Keep the backing storage alive until `send` returns. A nonzero status means
only that the host could not accept the message. The core forwards the name
unchecked. The UI matches it against the Card's declared views and shows an
error for an undeclared name. Argument and encoding errors throw before
the SDK calls the host. Invalid chart or point shapes and raw view names
containing a NUL byte throw `std::invalid_argument`.
The callback and its host context last for the process lifetime, so a
Card-owned thread can send its own data after `run` returns. Display
messages do not enter history.

An HTML view draws its empty state on load. It then receives a window
message with `{tsugumi: 1, port}`, where `port` is a transferred
`MessagePort`. Set `port.onmessage` to handle
`{type: "data", bytes: ArrayBuffer}` and
`{type: "run", state: "started" | "ended"}`. The view manages its own layout
and runs in an isolated frame without network access.

## Cancellation, deadlines and failures

During a call, any Card thread can poll `card::cancelled()` or read the remaining time in milliseconds with `card::remaining_ms()`. The reference SDK uses `-1` for a call with no deadline. Cancellation state is process-wide. Between calls these functions return `true` and `0`, respectively. A long-running loop should check cancellation between units of work.

Throw `tsugumi::Failure(kind, message)` for a structured failure. The default third argument, `std::source_location::current()`, captures the **construction site**. If a helper constructs the exception, give the helper its own default location and pass it through, as below. The reference SDK reports the source directory name, the path within it, and the line for Card sources. External source locations are omitted. An optional fourth argument identifies a notebook cell.

Here is a complete file-forwarding Card with a needed Path input `source` and a required Path output `original`.

```cpp
#include "card.hh"

#include <source_location>

namespace {

auto CheckCancellation(std::source_location where = std::source_location::current())
    -> void {
  if (card::cancelled()) {
    throw tsugumi::Failure(Tsugumi::Data::FailureKind::cancelled,
                           "Stopped before forwarding the file", where);
  }
}

}  // namespace

auto run(const Card::Inputs& input) -> Card::Output {
  CheckCancellation();
  Card::Output output;
  output.original = input.get<std::filesystem::path>("source");
  return output;
}
```

The adapter translates the exception into `CardResult.failure`. A reserved or unknown failure kind becomes `worker_failed` and its original numeric value is included in the message. The ABI return code is zero when a result carrying a failure was built. Nonzero means the adapter could not supply a result. Outputs of a failed call are discarded. The exact failure enum names are provisional SDK details.

## Files, directories and worker lifetime

A Path input is an absolute `std::filesystem::path` to a file or a directory. Treat inputs as read-only and use each path only during its invocation. With filesystem isolation enabled, the worker enforces read-only access. With isolation off, it supplies a private, writable copy to protect the stored original. An already-open file descriptor is not revoked when the path expires.

| Location | How to use it | Lifetime |
| --- | --- | --- |
| CWD, also `HOME` | Writable space for this Card's files and caches. Create new Path outputs here. | The process. A reused worker keeps the contents. |
| `TMPDIR` | Writable scratch. Read the path from the environment. | The path is fixed for the process. Its contents are cleared for each invocation. |
| `/tmp` | On workers that remap paths (Linux bubblewrap, shared VM, remote), this is the same managed, disk-backed scratch as `TMPDIR`. | On native macOS only `TMPDIR` has the scratch guarantee. |

For a **new output**, choose a name under the CWD, create the regular file or directory and assign its path to `output.<port>`. A directory can contain a tree of regular files. Links, paths under `TMPDIR`, and granted host paths are rejected for new outputs. There is no provided output directory or target path in the input.

Finish writing and close all output streams **before returning**, including writes on background threads. The worker snapshots newly created files after receiving the result and before clearing scratch or starting another call. Directory collection snapshots files individually. Each call has limits on total output bytes and entry count. To **forward** a Path input, return its path unchanged, as in the example above. Tsugumi records the original stored path without copying it. A symlink to the input does not qualify.

The [CSV filter template](../templates/filter-counts/) does both in one call. Its output schema declares both ports as `string (tsugumi: "path")`.

With `reuseWorker`, memory and CWD contents can survive across invocations and runs **of the same Card**. One worker takes one call at a time. It ends with the series of runs and is recreated when the definition, SDK, grants or a secret value changes. A call already executing when the definition changes finishes on the old version. A cache in `HOME` should therefore be safe to rebuild when the next call finds it missing.

## Secrets and grants

Read a declared secret by its declared name, for example `std::getenv("db_token")` from `<cstdlib>`. The worker injects it at process startup. Check for a null pointer before using the value and keep the secret out of displays and logs.

A person grants access to named host paths (read-only or read-write), the GUI or the network. Grants reach the Card through the process environment. For a named host path, the **provisional** spelling is `TSUGUMI_GRANT_<NAME>`, for example `std::getenv("TSUGUMI_GRANT_CALIB")`. Use the supplied path. Grant variable names and the declaration syntax for host paths and GUI grants are still open. An operation requiring a disabled grant fails inside the Card.

## Removed from the Card interface

The Card ABI exposes no run ID, invocation number or Card identity, including through the environment. There are no `Report` or `Run` arguments, init phase, `on_run_start`, `preRun` or `postRun`. Read typed parameters from the input and write diagnostics to stdout or stderr. The old `TSUGUMI_PARAMS_JSON` and `TSUGUMI_*_DIR` variables are gone. The ABI carries the parameters and typed table bytes in the FlatBuffers envelope. Path ports use its dedicated path field. There is no JSON input/output API, reflection or `bfbs` in the Card library.

The upstream decisions describe the [Card ABI](https://github.com/gen740/Tsugumi/blob/1610f0f934edbcc627babcfb6df59829e62d7c51/docs/CardABI.md), [sandbox contract](https://github.com/gen740/Tsugumi/blob/1610f0f934edbcc627babcfb6df59829e62d7c51/docs/SandboxContract.md) and [SDK boundary](https://github.com/gen740/Tsugumi/blob/1610f0f934edbcc627babcfb6df59829e62d7c51/docs/CoreAndSDK.md).
