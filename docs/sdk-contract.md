# Card SDK contract

The Card editor and the Agent use the same API generated by the Card's build.
The SDK builds this API from the current definition and wiring supplied as
FlatBuffers schemas.

## Nix entry

Tsugumi calls a Card's `default.nix` with `{ pkgs, params, inputs, schemas }`.

| Argument | Value |
| --- | --- |
| `pkgs` | The project's nixpkgs. |
| `params` | The Card's Nix-visible parameter values. |
| `inputs` | Upstream exports by input port, declared Nix sources under `inputs.sources`, and the SDK set under `inputs.tsugumi`. The SDK set is `import <kit> { inherit pkgs; }`. |
| `schemas` | A directory containing `_inputs.fbs`, `_outputs.fbs`, and `_params.fbs`. |

Pass `schemas` to the selected SDK builder. The Card returns `run`, optional
`exports`, and optional `views`.

```nix
{ pkgs, params, inputs, schemas }:
let
  sdk = inputs.tsugumi.cppSdk;
in
{
  run = sdk.cppCard { inherit schemas; src = ./src; };
  views = sdk.views;
}
```

Every SDK installs `lib/main.so` and the generated Card-facing API under
`share/tsugumi/api/` in the same output. Include the sources the Card author
writes against (for example `card.hh`, Python stubs, or generated Go or Rust
sources) and a `README.md` listing typed inputs, outputs, and params. Use the
same generated API for the library and the installed files.

## Inputs may be absent

`_inputs.fbs` describes the connected ports in declaration order. Each port's
type comes from its upstream output. A CardInput may omit an input. A Card
declares whether it needs an input in its own code. The SDK reports
`CardFailure.input_missing` with a message identifying the port when the Card
requests a needed value and it is absent. Optional inputs use the language's
absence value. The table gives the conventions for this revision's SDK ports.

| SDK | Needed | Optional |
| --- | --- | --- |
| C++ | `T` | `std::optional<T>` |
| Rust | `T` via `require_input(name, option)?` | `Option<T>` |
| Python | `input.require(name)` returns `T` | `input.get(name)` or a generated attribute returns `T \| None` |
| Go | `T` via `RequireInput[T](input, name)` | `*T` via a generated accessor or `OptionalInput[T](input, name)` |
| C# | `T` | `T?` |
| Java | `T` | `Optional<T>` |
| Ruby | Required lookup yielding a value | Optional lookup yielding a value or `nil` |
| R | Required lookup yielding a value | Optional lookup yielding a value or `NULL` |
| Julia | `T` | `Union{T, Nothing}`, absent as `nothing` |
| JavaScript | Needed value of type `T` | `T \| undefined` in the generated declarations |

A Path port is declared as `string (tsugumi: "path")`. Expose it as the
language's path type, or a string where the language uses strings for paths.
Read and write the path in `CardPort.path` with kind `Path` and empty `bytes`.
An input path is staged and absolute. Return a new regular file or directory
under the call's working directory, or return an input path unchanged to
forward it. A FlatBuffer port carries its payload in `CardPort.bytes`.

A mixed-type Merge uses `tsugumi.merge.Merged`. Expose its distinct member
types in the generated API and decode the nested FlatBuffer in the selected
box's `bytes` field inside the SDK. A same-type Merge forwards its input type
and bytes unchanged. Verify and decode SDK payloads in the SDK.

## Generator and checks

All generators use the shared [`tsugumi_ports` module](../sdk/codegen/tsugumi_ports.py)
to load the three schemas through FlatBuffers reflection. Use each SDK's
normal FlatBuffers compiler to generate its language bindings from those
schemas. Nix checks invoke Card definitions through the entry above, then
exercise `tsugumi_main` with the vendored ABI. The `sdkApi` check verifies
that each enabled builder publishes its API README.
